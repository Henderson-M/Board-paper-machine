# Board paper machine

A Claude Code skill that tracks NHS trust and ICB board meeting dates and board papers, analyses each newly published pack against HSJ editorial guidance, and emails the assigned HSJ correspondent.

## How it works

Two Claude Code skills, run from inside the repo directory:

- **`/scan-boards`** — the main weekly sweep. Scans 233 in-scope NHS trusts and ICBs for new meeting dates, generates `.ics` files, checks papers pages for meetings in the next 10 days, runs the pack-analyser on any new packs, and emails each correspondent the items relevant to their patch.
- **`/pack-analyser`** — a sub-skill, invoked by `/scan-boards` for each new pack, or directly by the user with `/pack-analyser` plus a papers URL. Reads PDFs, applies the editorial context, writes a structured tiered summary to `summaries/`.

State is held in `state/meetings.json` and pushed to GitHub after every run, so multiple team members can run the skill from their own machines without duplicating alerts.

By default everything is **dry-run** — emails are written as markdown files to `dry_run_output/` (gitignored). Pass `--live-emails` to actually send via Gmail SMTP.

## Layout

| Path | Purpose |
|---|---|
| `data/trust_urls.json` | 207 NHS trusts (197 in-scope) — ods_code, names, board page URL, correspondent. Maintained by the skill as it learns. |
| `data/icb_urls.json` | 36 ICBs — same plus merger/cluster metadata. |
| `data/correspondents.json` | Maps correspondent first name → email address. |
| `state/meetings.json` | Known meetings + their status (date_found / papers_found / analysed). Updated every run. |
| `summaries/` | Markdown summaries of analysed board packs — one per meeting. Generated by `/pack-analyser`. |
| `ics/` | `.ics` calendar files, one per detected meeting. Attached to alert emails as `text/calendar; method=PUBLISH` so Outlook renders an inline "Add to calendar" button. |
| `context/hsj_editorial_context.md` | Editorial guidance loaded by `/pack-analyser` every run. Defines the "north star" test, the tiered output format, signal patterns, and worked examples (Part F). |
| `.claude/skills/scan-boards/` | The main skill. |
| `.claude/skills/pack-analyser/` | The pack-analyser sub-skill. |
| `send_email.py` | Gmail SMTP helper invoked by `--live-emails`. Reads creds from `.env.local`. |
| `.env.local` | Local secrets (Gmail app password, HSJ CMS API token). Gitignored. |

## Setup

1. `git clone https://github.com/Henderson-M/Board-paper-machine.git`
2. Open the folder in Claude Code.
3. Verify your name appears in `data/correspondents.json` with the right email.
4. Create a local `.env.local` with the Gmail credentials (ask Henry):

   ```
   GMAIL_USER=hsjboardpapers@gmail.com
   GMAIL_APP_PASSWORD=...
   HSJ_API_TOKEN=...
   ```

5. Run `/scan-boards` — dry-run by default. Emails are written to `dry_run_output/`.
6. When satisfied, run `/scan-boards --live-emails` to actually send.

## Common commands

| Command | What it does |
|---|---|
| `/scan-boards` | Full sweep (dates + packs). Dry-run emails. |
| `/scan-boards --correspondent Henry` | Only orgs assigned to Henry. Useful for testing a personal patch. |
| `/scan-boards --dates-only` | Skip pack detection. Just refresh meeting dates. |
| `/scan-boards --packs-only` | Skip date scanning. Only look for new packs in the 10-day window. |
| `/scan-boards --live-emails` | Send real emails via Gmail SMTP. |
| `/pack-analyser <papers_url>` | Analyse a single pack ad-hoc. Writes to `summaries/`. |

## Cadence

The tool is **user-triggered**, not scheduled. Run twice a week as a default:

- **Mid-week** — picks up new meeting dates announced since the last run.
- **End of week** — picks up board packs that drop in the run-up to next week's meetings.

The 10-day pack-detection window means you don't miss packs published on the day or day before a meeting.
